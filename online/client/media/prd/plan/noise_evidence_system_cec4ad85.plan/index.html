噪声取证系统（新 pages 目录）

目标与边界

  • 目的：现场采集可回放的 时间 + 视频/音频 + 分贝（A 计权 Lp） 证据链，支持本地历史、删除、导出/导入、回放分析。
  • 不动 pages/media/ 及 /media 路由；新入口单独路由与侧栏项（如「噪声取证」→ /noise-evidence）。
  • 技术栈：沿用 Astro + Vue3、现有 Layout.astro 全屏模式；只读复用 media/lib/audio-meter.ts、permissions.ts、settings.ts 中计权/采集逻辑（不在 media 目录改代码，必要时在新目录做薄封装）。

采集页 vs 播放器（与现监控对齐 + 差异）

与 MediaMonitor.vue 一致的部分

  • 单 Canvas 主视觉：时钟、仪表盘 Lp、Min/Avg/Max、Leq 波形区（样式沿用 renderer.ts 色板与布局习惯）。
  • 底栏：麦克风 / 摄像头按需 / 翻转 / 录屏（可选 V1 仅摄像头+麦）/ 设置（满幅 fsRef、响应速度等可复用 settings 结构，独立 localStorage key，避免污染 toolkit-media-settings）。

采集页新增

  • 实时频谱：主线程或 Worklet 侧已有功率谱时，取 对数频段 32 条 画条形/渐变（与 Lp 同源，不另开 essentia 实例）。
  • 录制状态：顶栏或底栏「REC + 时长」；停止后写库并跳转首页或回放。

采集页刻意不做

  • 不对用户播放采集音频（分析链可 silent gain，与现 meter 一致）。

播放器新增

  • HTML5 video/audio 控制进度；Canvas 显示 录制开始时刻 + 当前偏移 的 wall-clock 时间（startedAt + currentTime）。
  • 曲线/频谱：优先 读已存 metrics；若某段无频谱数据，回放时对 已存 audio Blob 按需补算（可选 V2，V1 可只显示 Lp 曲线 + 实时频谱）。

存储方案（IndexedDB + 是否存分贝/频谱）

原则：取证核心是 可核验的时间轴 + 原始音视频；可视化数据为 可重建但宜缓存 的衍生数据。

建议存储内容（推荐默认）

数据是否存说明
视频 Blob可选存摄像头开则 MediaRecorder 视频轨；关则仅音频
音频 Blob必存单独 audio/webm 或与视频 mux；回放与再分析基准
metrics 时间序列强烈建议存约 2 Hz：{ tMs, lpA, leqA? }；整段 1h ≈ 7200 点，JSON 几十 KB，回放曲线零重算
频谱摘要建议稀疏存1 Hz、32 个对数频段 能量（Float32 或 uint16 量化）；1h ≈ 3600×32×2B ≈ 230KB；足够回放「频谱动画」
全分辨率 2048-bin @ 12Hz不存体积过大，无取证必要

不存也可工作：仅音视频 + 开始/结束时间；回放时对整段音频离线分析——手机 CPU 高、seek 慢，不推荐作为默认。

分块写入（防崩溃丢数）：采集中每 10s 将 metrics/spectrum 追加写入 IDB 的 chunks 子记录，结束时 merge 到 recordings 主记录并标记 complete。

IndexedDB Schema（V1）

  • DB 名：toolkit-noise-evidence，version 1
  • recordings（主索引 id，按 startedAt 排序）
    • id, startedAt, endedAt, durationMs, title?, videoMime, audioMime, hasVideo, bytesTotal, fsRef, deviceNote?, status: 'recording'|'complete'|'failed'
  • blobs（recordingId + kind: 'video'|'audio'）→ Blob
  • metrics（recordingId）→ 单 Blob：application/octet-stream 紧凑二进制或 gzip JSON
  • spectrum（recordingId，可选）→ 同上

封装：lib/storage/db.ts + recordingRepository.ts（list / get / delete / appendChunk / finalize）。

导出 / 导入

格式：.nrec.zip（无新依赖可用 JSZip 或 手动 ZIP；若加依赖优先 fflate 体积小）

manifest.json    # id, startedAt, endedAt, fsRef, thresholds, mime types
metrics.bin      # 或 metrics.json
spectrum.bin     # 可选
video.webm
audio.webm
  • 导出：从 IDB 读主记录 + blobs，打包下载。
  • 导入：解压校验 manifest → 生成新 id（保留原 startedAt 作展示）→ 写入 IDB → 首页列表可见 → 进播放页。

首页 UI

  • 采集：跳转 /noise-evidence/capture（首次进入再请求麦克风/相机，逻辑同现监控「开始只麦、相机按需」）。
  • 导入：<input type="file" accept=".zip,.nrec.zip">。
  • 历史列表：时间倒序；项展示开始时间、时长、峰值 Lp、是否有视频；操作 回放 / 导出 / 删除（删除确认）。
  • 可用空间：navigator.storage.estimate() 的 usage/quota 进度条 + 文案「已用 x / 可用 y」；辅以本地 sum(recordings.bytesTotal) 与 quota 对照（quota 含全站 IDB）。

样式：白底卡片列表 + 现有 --danger 主色按钮，与 MediaSettings.vue 弹窗风格一致；移动端列表全宽、底栏安全区。

播放页：昼/夜阈值与红边

  • 阈值（默认，可后续进设置）
    • 昼（本地 06:00–22:00）：Lp(A) > 55 dB 触发
    • 夜（22:00–06:00）：Lp(A) > 45 dB 触发
  • 判定时刻：startedAt + media.currentTime 的本地小时，决定用哪条阈值（跨昼夜录制按当前播放点切换）。
  • UI：全屏 四边渐变红色遮罩（参考导航超速），强度随超标幅度 min(1, (lp - limit) / 10) 增加；非全屏闪断，避免癫痫式闪烁（最短保持 300ms）。
  • 数据源：回放优先用 metrics 里 lpA；无 metrics 时对 audio 实时 meter（与采集同源）。

频谱实现（V1 轻量）

  • 采集/回放共用：从 meter Worklet 的 msA 同源功率数组 或 Analyser getFloatFrequencyData（若后续 CPU 优化第一刀）取 32 频段聚合。
  • Canvas 区域：波形下方或右侧增加 SpectrumPanel（条形图）；播放 seek 时按 tMs 二分查最近 spectrum 帧。

实施分期

Phase 1（MVP 取证闭环）

  • 首页 + IDB CRUD + 采集（音视频录制 + metrics 2Hz）+ 播放（音视频 + 曲线 + 时间 + 红边）+ 删除 + ZIP 导出/导入（manifest + audio 必含，video 可选）。

Phase 2

  • 稀疏 spectrum 存储与回放；存储条更精确；采集页设置与 CPU 优化（Analyser 替 essentia）可并行。

Phase 3

  • 录屏源、Leq 窗口导出报告摘要、批量导出。

风险与约束

  • Safari/iOS：MediaRecorder mime 需探测 video/webm;codecs=vp8,opus 降级；单文件过大受 IDB/quota 限制，长录需提示剩余空间。
  • 隐私：纯浏览器本地，不上传；导出文件含音视频，需 UI 提示。
  • 与 /media 关系：长期可把 audio-meter 抽到 src/shared/slm/，本计划 V1 仅 import 只读，避免双份 essentia 加载（capture/play 各开一次 meter 即可）。

验收要点

  1. 新路由可访问，侧栏进入；/media 行为不变。
  2. 采集结束 IDB 有记录；列表可删；导出 ZIP 清空浏览器后导入可播。
  3. 回放时间与录制 startedAt 一致递增；昼/夜切换阈值正确；超标红边可见。
  4. 采集中无扬声器出声；播放页可听音频。
  5. 首页 quota 进度条随导入/删除变化。
