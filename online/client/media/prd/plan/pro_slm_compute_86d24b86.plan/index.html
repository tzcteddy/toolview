专业噪声计算（UI 不变）

对照上次评估里未达标项。目标是 IEC 61672 对齐的工程级 Web 声级计，不是法定 Class 1/2（浏览器拿不到 20 μPa 与每只麦的灵敏度）。UI / 布局 / 文案控件一律不改；只改采集与计算，以及出厂默认（底噪跟踪改为关）。

主动接受的观感变化：安静房间不再被拉到 35–45。同一物理环境在不同设备上读数仍会因麦灵敏度差几 dB，但相对变化、A/C 差值、Leq 积分会按标准走，不再被 AGC 和「校准到 40」抹平。

flowchart TB
  gum[getUserMedia_rawAudio]
  gum --> ctx[AudioContext_48k]
  ctx --> essentia[essentia.js_WASM]
  essentia --> iir[IIR_or_Spectrum]
  iir --> weight[IEC_A_C_Z_weights]
  weight --> tw[TimeWeight_ms]
  tw --> leq[Leq_energy_dt]
  tw --> map[dBFS_plus_deviceTrim]

策略（按设备自己定）

  • 采集（PC/手机相同约束，失败再降级）：关闭 echoCancellation / noiseSuppression / autoGainControl，单声道，尽量 48 kHz。OverconstrainedError 时先丢掉 sampleRate，再退回 audio: true。
  • 重计算只用一个第三方库：essentia.js（MTG/UPF，WASM）。窗函数、FFT/频谱、IIR 滤波全部走该库，禁止再手写 1024 点乘加或自研 FFT。本仓库只保留 IEC A/C 权曲线、时间加权、Leq 积分与 dB 映射。进入监控页再懒加载；Worklet 用官方 essentia-wasm 同步构建。WASM 失败才退 Analyser，降级路径仍用 essentia 对时域帧做 Windowing + Spectrum，能量 Σ P·w（不除以 Σ w）。帧长：PC 4096，手机 2048。许可为 AGPL-3.0，依赖写在 packages/toolkit-online。
  • 主路径仍在 AudioWorklet：essentia IIR 吃 IEC 系数做 A/C，Z 为不计权。时间加权仍对应现有快/中/慢（125 / 250 / 1000 ms）。Leq 用 Σ p²·Δt / T，不用帧平均。
  • 绝对刻度：Lp = 10·log10(ms) + 120 + trim（0 dBFS = 120 dB）。trim：桌面 0，iOS -3，Android -6。1.5 s「校准中」只做滤波器稳定，不再把环境映射到 40。
  • 底噪跟踪：出厂改为关；打开时只做极慢的增益漂移补偿，不瞄准 40 dB。现有开关保留，不改 UI。
  • C 计权：公式按标准算，不在手机上虚增低频（会放大底噪、冒充冲击）。移动端默认仍关 C（现有逻辑）。手机麦 100 Hz 以下硬件缺口无法软件补齐。
  • 不做：新校准 UI、过载新控件、改侧栏/主题、宣称计量认证。底部署名保持「仅作参考」。

改动范围

只动 packages/toolkit-online 的 media 页、public/media/，以及该包对 essentia.js 的依赖。不改 Vue 模板结构。

1. 原始音频采集

permissions.ts 抽出 rawAudioConstraints()，requestCameraAndMic 的合并/单独麦请求都走它，带降级。

2. Worklet + essentia 测量核

新增 public/media/meter-processor.js（base 为 /toolview/online/client，用 import.meta.env.BASE_URL 加载）。Worklet 内加载 essentia WASM。

每块音频：essentia IIR（A/C）或 Windowing+Spectrum → IEC 权 → 均方时间加权 → 按 leqWindowMs 滑窗积分。主线程用 MessagePort 收最新 msA/msC/msZ 与能量和；C 关闭时跳过 C 路。

3. AudioMeter 接入与降级

改 audio-meter.ts：

  • start()：懒加载 essentia，优先 audioWorklet.addModule；失败则 Analyser 取时域帧，仍交给 essentia 做频谱。
  • tick()：只做映射、钳位 0–120、波形/统计；rAF 不再手写 FFT 乘加。
  • 删除「P35 → 40 dB」和「向 40 爬」；finishCalibration 只置 floorReady。
  • setCWeightEnabled / setLeqWindowMs / setResponseSpeed 转发 Worklet。

4. 设备 trim 与默认

小表（UA：iPhone/iPad → ios，Android → android，其余 desktop）加到 audio-meter.ts。
settings.ts：noiseFloorTrack 出厂 false，normalize 用 === true（与 enableCWeight 一致）。重置即关跟踪。

MediaMonitor.vue 仅随 start() 契约改调用，不改画面。

验收（chrome-devtools，UI 截图像素级对照即可）

  1. 授权后 getSettings()：能关则 AGC/NS/AEC 为 false。
  2. 1 kHz 类激励：dBA ≈ dBC；模拟低频（降采样或低频振荡）dBC 明显高于 dBA（修复除 Σw 后差值应拉开）。
  3. 安静环境：读数稳定，不被锁在 40；关跟踪后 offset 不再爬。
  4. 开/关 C、重置、波形勾选规则、右侧铺满、齿轮/摄像头/录屏：行为与现 UI 一致。
  5. 模拟移动 UA：C 默认关；essentia/Worklet 失败时帧长 2048 且页面不挂。
  6. 控制台/网络可见 essentia WASM 已加载；分贝路径不依赖手写 FFT。
